# Promote to project

**Status: skeleton / not implemented.**

When explicitly selected, say briefly that this is a design stub. Use the request to identify the relevant intended mode below, then show the proposed inputs, outcome, and missing capability. Mark unknown inputs as unknown; do not ask a setup questionnaire for a workflow that cannot run yet. If the request is to review or change the surface, discuss the design at that scope.

## Intended use

Promote an accepted thread-local item into shared project knowledge while preserving its origin and conflicts.

Example: “Use $promote to make this accepted decision part of the project’s shared context.”

## Intended modes

- Identify the specific accepted decision, constraint, fact, artifact, or tangent disposition.

- Inspect the destination project scope and revision.

- Preview the shared-state change, merge compatible material, and expose conflicts.

- Record source workstream/revision and leave the original item/history intact.

## Inputs

- Explicitly selected item and evidence of acceptance

- Source identity/revision

- Destination project and current shared-state revision

## Observable outputs after implementation

- Project-state revision and provenance link

- Conflict or merge result

- Originating item’s promotion relationship

## Supporting capabilities — not implemented

- `promotion`: Project knowledge promotion.

- `workstreams`: Revisioned workstream state and discovery.

- `ideas`: Faithful idea capture and contextual views.

- `evidence`: Evidence, assumptions, and decisions.

Read [the capability contracts](../../docs/CAPABILITIES.md) only when reviewing these dependencies. These are design names, not callable tools or declared MCP connections.

## Scope boundary

An assistant suggestion is not an accepted fact. Project promotion is distinct from personal memory, Beads task creation, and bootstrapping a new initiative. Broader visibility must remain deliberate.

Negative activation case: A speculative tangent must not become an approved project commitment merely because it was captured.

## Open design question

Should promoting a tangent mean linking a project idea, accepting a project fact, or offering those as different destinations?
